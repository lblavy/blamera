# M3-04 — reconnaissance faciale dans la photo stable

2 novembre 2026, baseline `83d3645`. Périmètre UI, galerie intégrée et décision.
Le runtime natif, ses poids et ses preuves numériques ont un propriétaire distinct.
Les sources de ce lot sont en cours de qualification ; aucune preuve appareil
n'est déduite des tests UI exécutés sur PC.

## Parcours et données

Une capture, un import ou Analyser sur une zone prépare également la reconnaissance
faciale locale lorsque la galerie est prête. Le chargement tardif de la galerie et
son remplacement relancent uniquement l'image courante. Aucun appel natif ne part
au rerender Compose. Le flux caméra reste un aperçu ; pas de reconnaissance live.

L'application lit d'abord la galerie chiffrée existante. Si elle est absente, elle
peut lire le seul asset optionnel généré `faces/bootstrap.json`, le valider avec le
contrat v1, puis le chiffrer avant publication. Une galerie valide existante est
conservée ; une galerie enregistrée corrompue n'est pas silencieusement remplacée.
Une APK générique sans asset de bootstrap reste normale, sans galerie configurée.
Le fichier personnel est fourni au build par l'orchestrateur sur demande explicite
de l'utilisateur ; il n'est pas ajouté aux sources ni aux fixtures publiques.

Le paquet fournit les prototypes et la politique. La décision n'invente pas de
seuil mobile : mêmes normalisations L2, cosinus borné, classement par score puis
ID pour les égalités, rejet strict sous le seuil, acceptation et marge inclusives.
Une seule identité garde ses seuils absolus, sans second score artificiel.
Les vecteurs invalides ne produisent pas une identité forcée. Le calcul utilise
des Double et une accumulation compensée, pas des pourcentages de confiance.

## Interface et cycle de vie

Un seul visage détecté donne un rectangle et son nom, Inconnu ou Identité incertaine.
Le rectangle emploie les coordonnées source du moteur et exactement le viewport
de l'image, y compris zoom, déplacement et rotation de l'interface. Les labels
sortis du cadrage visible ne flottent pas sur l'image. Le panneau garde une phrase
accessible. Plusieurs visages invitent à cadrer une personne, sans en choisir une.

L'analyse faciale est indépendante des contours, sélections, actions ChatGPT/Lens
et informations botaniques. Les noms des personnes ne sont pas injectés dans les
prompts externes. Une erreur du moteur facial ne remplace pas l'image ou les autres
résultats par une erreur globale.

Chaque changement de photo, de galerie, de navigation ou passage en arrière-plan
annule le résultat facial en cours et rend les réponses tardives inapplicables.
Le retour au premier plan redémarre une seule analyse si nécessaire. La rotation
conserve le contrôleur du ViewModel. Image entière relance un résultat correspondant
à l'original, au lieu de réutiliser une ancienne boîte du recadrage.

La conversion Bitmap→RGB se fait hors du thread UI, par lignes, sans mutation ou
recyclage du bitmap emprunté. Elle ne redimensionne pas l'image et écarte l'alpha
comme la conversion RGB du producteur PC. Le contrat des photos décodées borne
chaque côté à 2048 pixels ; un bitmap hors contrat échoue seulement pour le visage.
Le moteur est fermé une fois par son propriétaire ; sa fermeture non bloquante
est le contrat du runtime natif.

Les fixtures sont synthétiques et publiques. Les tests séparent les mathématiques
de décision, les races et l'état logiciel, les pixels du dessin, le vrai runtime
natif et les mesures sur le téléphone. Les versions, commandes Green, métriques
et limites finales seront complétées après qualification indépendante.

Premier Green intégré : `green-ui-emu-build.log`, sortie0, **26 tests réussis**,
sans échec ni test ignoré, comprenant cinq compléments utiles de races et de
présentation. Les APK génériques x86_64 et de test sont assemblées avec couverture
pour l'émulateur PC uniquement ; aucune galerie personnelle n'y est intégrée.
Le moteur SDK est encore une façade dans ces APK, afin de prouver le Red natif
séparément. Ces tests UI ne prouvent donc ni le fonctionnement JNI ni une
reconnaissance réelle. Format, analyse statique, mesures par composant et contrôle
global final restent à exécuter sur l'état intégré avec le vrai bridge.
