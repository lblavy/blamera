## Temps observés — pas de budget Android

Chaque mesure comporte **3 échauffements puis 20 répétitions** ; toutes les valeurs
individuelles sont conservées. Images déjà en mémoire, export et chargements exclus.

| Fixture / mesure | Médiane native / ORT (ms) | P95 native / ORT (ms) |
| --- | --- | --- |
| Astronaut, forward brut | 76,59 / 65,65 | 111,24 / 81,22 |
| Astronaut, chaîne prétraitement→NMS/masques | 67,51 / 48,37 | 88,36 / 51,25 |
| Synthétique, forward brut | 72,81 / 77,12 | 79,32 / 90,28 |
| Synthétique, chaîne complète | 82,07 / 61,68 | 95,17 / 91,53 |

Le PC expose 12 CPU logiques. Le champ `threads=4` du résultat est la **requête initiale**,
pas une instrumentation des threads de chaque phase : la sélection CPU Ultralytics
réinitialise les threads PyTorch et son wrapper ORT garde ses valeurs par défaut.
Seule la session ORT directe fixe explicitement 4 threads intra-op / 1 inter-op.
Ces temps décrivent cette recette, sans conclure à une accélération à threads contrôlés
ni comparer directement temps brut et chaîne complète. Pas de FPS cible déduit.

RSS échantillonné après les essais : **783 495 168 octets (~747 Mio)** pour le processus
qui conserve PyTorch, ORT, export et outillage. Ce n'est ni un pic mémoire contrôlé,
ni la mémoire Android attendue. Aucun GPU, chauffe, mémoire ou latence téléphone mesuré.
