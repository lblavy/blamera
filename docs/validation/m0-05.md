## Réserve du tester : diagnostics UTF-8

Le testeur a constaté un `UnicodeDecodeError` dans un thread de lecture de subprocess :
le décodage implicite cp1252 ne pouvait pas lire une sortie UTF-8 de complexipy.
Le JSON prouvait toujours le rejet de la complexité ; le problème concernait le diagnostic.
Le coder a reproduit le constat avec :

```powershell
.\pc\.venv\Scripts\python.exe -m unittest discover -s scripts/tests -p test_pc_tools.py -k test_real_ruff_and_complexipy_reject_excessive_complexity -v
```

Avant correction : **sortie 0 / 1 test réussi**, mais exception de décodage dans un thread.
Ce n'est pas présenté comme un test fonctionnel en échec. Log local :
`.gradle-user-home/m0-05-encoding-before.log`.
Les cinq captures de sorties dans `test_pc_tools.py` fixent maintenant
`encoding='utf-8', errors='replace'` ; les preuves et assertions restent inchangées.
Après correction, la même commande sans filtre `-k` exécute le module complet :
**sortie 0 / 3 tests réussis**, sans `UnicodeDecodeError` ni exception de thread.
Log local : `.gradle-user-home/m0-05-encoding-after.log`.
Aucune passe globale supplémentaire n'est nécessaire pour ce changement de diagnostics uniquement.
Le reviewer puis le tester ont vérifié cette correction : conformes, module ciblé
3 tests réussis, réserve levée. Le socle M0-05 est définitivement validé localement.
