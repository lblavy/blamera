## Corrections et limites

- Cycle 1 de revue : correction du calcul du nouveau code Python. Une docstring exécutée
  était comptée avec les instructions, permettant à 3/4 instructions réelles de devenir
  un faux 80 %. Les deux tests de régression ont échoué avant correction (37 tests,
  2 échecs fonctionnels), puis la suite corrigée passe (38 tests). Le cas limite est
  maintenant mesuré à **75 % et rejeté**. L'ensemble canonique provient de l'API publique
  `Coverage.analysis2` ; absence/incohérence de ces données bloque le gate.
- detekt CLI stable isolé, sans résolution de types, compatible avec la syntaxe actuelle ;
  le compilateur Kotlin reste la preuve des types. Aucun plugin alpha imposé dans la compilation.
- Champ `serialVersionUID` explicite ajouté à l'état sauvegardé avec **l'UID calculé de la première
  version**, plutôt qu'une valeur arbitraire rompant sa compatibilité. La restauration passe sur PC.
- Avertissements concrets de ressources traités : icône monochrome, suppression du qualificateur
  obsolète et règles explicites excluant sauvegarde/transfert des données de l'application.
  Il ne s'agit pas d'une modification des paramètres ou sauvegardes du téléphone.
- Les suggestions de versions plus récentes sont conservées : SDK 36 et compatibilités épinglées
  priment sur une mise à jour aveugle. Le décalage XML SDK v4/v3 reste signalé, sans échec de build.
- Le scan OSV/licences couvre le runtime Android debug. Dev/test et transitifs des outils,
  JDK/SDK et futurs modèles sont hors de ce scan : aucune absence de vulnérabilité globale n'est prétendue.
- coverage.py est installé uniquement dans `.tools/python-quality`, jscpd dans `node_modules` ;
  leurs versions sont épinglées. Aucune installation système Python ou outil ML n'a été faite.
